**原始发现：3 项 P1，其中 2 项待处理、1 项已关闭**

1. **P1 · `hidden: true` 的原文仍在公开仓库中。**

   位置：`apps/site/source/_posts/2026/04/15/openai-codex-源码解析-它为什么必须是一个带-harness-的本地-agent.md:18`，以及另外 3 篇隐藏文章。

   GitHub API 确认仓库为 public；直接读取公开 main 分支上的这篇文件成功，内容包含 `hidden: true`。因此即使站点不导出正文、API 做了作者鉴权，仍可从仓库获取原文。公开仓库地址：[ffffhx/garden-lab](https://github.com/ffffhx/garden-lab)。

   建议：明确区分“隐藏列表”和“保密内容”。需要保密的 Markdown 与附件应存放在私有内容仓库或仓库外的数据目录，公开构建只接收公开内容。已经公开的历史副本不能仅靠设置 hidden 撤回。此项没有发现或宣称凭证泄漏。

2. **P1 · 标为“仅自己可见”的健身栏目，8 篇文章仍被公开导出。**

   位置：`apps/site/components/root-chrome.tsx:22`、`apps/site/lib/content/posts.ts:223`、`apps/site/lib/content/posts.ts:243`、`apps/site/scripts/gen-agent-post-index.ts:11`。

   私有控制发生在前端栏目入口，但内容加载器只按 `hidden` 过滤。生产产物中存在 `/post/fitness-start-first/index.html`，公开 `agent-post-index.json` 包含全部 8 篇健身文章：`deadlift-form`、`bench-press`、`squat-form`、`strength-big-three`、`muscle-gain`、`fat-loss-beginner`、`fat-loss-method`、`fitness-start-first`。这些静态文件不经过 API 鉴权。

   建议：在内容层统一决定公开/私有状态，让页面生成、索引、附件发布和 API 导出使用同一规则；若健身确实应当公开，则取消“仅自己可见”的错误承诺。

3. **已关闭（原 P1）· Lark 回调在缺少鉴权配置时默认放行。**

   原位置（文件已删除）：`tools/lark-codex-bot/src/server.mjs:71`、`:794`、`:872`、`:2266`。

   `validateConfig` 不要求回调验证 Token 或 Encrypt Key；没有 Encrypt Key 时明文事件不校验签名，没有 Token 时 `verifyPayloadToken` 直接返回。服务监听没有指定 loopback 地址，默认用户/群白名单也为空。独立执行配置与 Token 验证函数确认：缺少鉴权配置、空 Token 的输入被接受。

   影响：如果操作者遗漏环境变量且回调端口可被访问，伪造事件可以进入本地 Codex 任务链路。尚未检查实际部署是否具备额外网关防护，也没有向真实回调发送执行任务。

   建议：local/hub 回调服务缺少所需鉴权配置时拒绝启动；明确监听地址，生产校验签名、Token 及允许的调用者。调试模式应使用明确开关和 loopback 绑定。

**功能、发布和交互：12 项 P2**

4. **P2 · OAuth state 有签名，但没有绑定发起登录的浏览器。**

   位置：`apps/garden-api/src/auth.ts:84`、`:98`；`apps/garden-api/src/server.ts:129`、`:147`。

   登录起点生成带 nonce 的 state，却没有把对应值保存在发起浏览器的 Cookie 或服务端登录事务中；回调只验证签名和过期时间。这能验证 state 是本站签发的，不能证明回调属于当前浏览器发起的那次登录，存在登录 CSRF 风险。此项为代码确认，没有操作真实 GitHub 登录来进行攻击复现。

   建议：将一次性登录事务与安全 Cookie 绑定，回调核对并消费，处理过期、重复回调和登录取消。依据：[OAuth 2.0 RFC 6749 §10.12](https://www.rfc-editor.org/rfc/rfc6749#section-10.12)。

5. **P2 · 部署没有等待测试与类型检查通过。**

   位置：`.github/workflows/pages.yml:4`、`:48`、`:56`；`.github/workflows/ci.yml:28`。

   CI 与 Pages 工作流都由 main push 独立触发。Pages 的 deploy 只依赖自己工作流里的 build，因此测试失败但 Next 构建成功的提交仍可能发布。这次检查并未触发部署。

   建议：让部署依赖同一提交的完整校验，或在 Pages 工作流复用验证 job；复用同一构建产物，避免两套发布配置继续分歧。

6. **P2 · 文档中的生产启动命令不能使用。**

   在成功构建的独立副本中运行 `pnpm start -- --port 3012`，进程退出，报错 `"next start" does not work with "output: export" configuration`。

7. **P2 · 按文档新建每日新闻，文章不会进入新闻模块。**

   位置：`apps/site/scripts/new-entry.mjs:113`；`apps/site/lib/content/daily-news-date.ts:13`；`apps/site/lib/content/daily-news.ts:153`。

   在隔离目录执行新闻生成器，标题 `2026-09-10 AI 与前端热点速览` 被原样写入；模块却只接受以 `每日新闻：` 或 `每日新闻:` 开头的标题，因此会将它过滤掉。模板默认的“新闻速览”标题也没有使用条目统计要求的编号新闻格式。

   建议：使用明确的内容类型与期刊日期字段识别新闻；生成器与读取器共享 schema，生成符合正文条目规则的模板。

8. **P2 · 本地预览强制显示作者模式，却没有建立 API 登录状态。**

   位置：`apps/site/components/private-feature-access.tsx:254`、`:283`、`:352`；`apps/site/app/private-post/page.tsx:64`。

   localhost/127.0.0.1 会直接进入 `allowed` 并跳过 `/api/auth/me`，登录按钮也被作者模式替代。实际本地启动在没有配置 API 时显示“作者模式”，私有文章页却显示“未配置 Garden API 服务地址”；配置 API 后，若无有效凭证，后端仍会拒绝正文请求。前端的模拟身份无法通过后端鉴权。

   建议：把真实作者身份与显式开启的 UI 预览模式分开；本地开发提供完整登录流程或仅用于开发的配套测试身份。权限错误和服务连接错误也应分开呈现。

9. **P2 · 私有文章列表用中文展示日期排序，解析结果为 NaN。**

   位置：`apps/garden-api/src/private-blog.ts:42`；`apps/site/lib/content/private-post-export.ts:59`；`apps/site/lib/utils/date.ts:35`。

   导出格式移除了原始 Date，只保留类似 `2026年8月21日` 的 dateText。API 又执行 `new Date(dateText).getTime()`。本机 Node 验证不能解析该字符串，比较器失效，列表无法保证按时间倒序。现有导出测试使用 ISO 风格 dateText，未覆盖真实内容格式。

   建议：JSON 单独保存 ISO 日期或时间戳用于排序，dateText 只负责展示。列表合并也应按统一日期排序，而不是始终将私有文章插在公开文章之前。

10. **P2 · 手机长文目录位于整篇正文之后。**

    位置：`apps/site/components/article-layout.tsx:26`、`:56`。

    xl 以下网格变为单列，但 DOM 顺序仍是正文后接目录。窄屏查看 ProfilePilot 文章时，目录起点约在页首下方 58,893 CSS 像素；用户必须先读完整篇文章才能看到导航。

    建议：手机使用正文前的可折叠目录或固定目录入口，桌面保留侧栏；没有目录的文章应考虑取消空侧栏。

11. **P2 · 新闻页滚动时，目录高亮不会跟随正文。**

    位置：`apps/site/components/post-toc.tsx:58`；`apps/site/components/daily-news-module.tsx:303`。

    桌面新闻正文在 `.daily-news-pane` 内滚动，目录组件却监听 window scroll。实测正文容器滚动约 2,575 像素、window.scrollY 仍为 0，第二条新闻已经进入视口，高亮仍停在“今日重点”。

    建议：目录接受实际滚动容器并监听它，或使用以该容器为 root 的 IntersectionObserver。新闻日期档案很长，也不宜将当期目录放在整份档案之后。

12. **P2 · 手机菜单在跳转后保持展开，遮住新页面。**

    位置：`apps/site/components/site-header.tsx:184`。

    实测展开菜单后点击“技术”，页面完成导航，但 `<details>` 仍然展开并遮住分类标题。当前组件没有随 pathname 改变关闭菜单的逻辑。

    建议：导航成功后关闭菜单，补充 Escape 和点击菜单外关闭；保留合理的焦点行为。

13. **P2 · 图片灯箱无法完成键盘访问，触屏平移也缺少支持。**

    位置：`apps/site/components/article-image-lightbox.tsx:53`、`:124`、`:224`、`:291`。

    MR 文章正文图片 tabIndex 为 -1，没有等效按钮或键盘触发入口。点击图片打开 dialog 后，焦点仍在 BODY；按 Tab 后焦点进入背景代码块 PRE，而非弹窗控件。虽然有 Esc 和缩放快捷键，但没有初始焦点、焦点限制和关闭后的焦点恢复。平移事件仅实现 MouseEvent，触屏放大后的平移操作也未覆盖。

    建议：提供可聚焦的图片放大入口，使用正确的模态焦点管理；以 Pointer Events 统一鼠标和触摸操作，提供键盘等效操作。验证依据来自实际页面行为及代码。

14. **P2 · 健身文章保留了 4 个失效的旧站内部地址。**

    位置：`apps/site/source/_posts/2026/04/16/三大项力量训练不是硬拼而是把技术训练量和恢复做对.md:43`，及卧推、深蹲、硬拉文章中的互链。

    静态导出检查发现以下目标没有对应页面：`/garden-lab/posts/2026/04/16/ee53c9fe60c5/`、`ffc14b00b7df/`、`0b511a0d7cca/`、`23da0d996380/`。当前页面使用 `/post/<slug>/`，并未为这些旧路径导出重定向。

    建议：建立旧地址到稳定 slug 的迁移映射，改写正文链接，并在构建后检查站内链接。该检查针对直接引用的静态路径，不包含外链可用性或浏览器中的所有动态请求。

15. **P2 · 图片普遍没有预留尺寸，加载时容易产生布局位移。**

    位置：`apps/site/components/post-card.tsx:82`；`apps/site/components/article-layout.tsx:14`；`apps/site/lib/content/markdown.ts:75`。

    导出 HTML 中扫描到的 240 次 img 出现均未同时提供 width/height；封面容器也没有固定 aspect-ratio。浏览器检查封面确认尺寸属性为空，代码仅设置 w-full/h-auto。慢网或图片尚未缓存时，无法预先确定图片占位高度。本次没有测量生产环境的 CLS 分数，不能据此给出具体性能分值。

    建议：内容构建时提取原始图片尺寸；统一比例封面可以先提供 aspect-ratio，占位比例不应强制套用到所有正文图片。[Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 同样要求图片尺寸与键盘可访问性。
