# 2026-09-07 本地预览内存排查

## 结论与边界

Windows 事件 2004 证实 PID 34920（garden-lab 的 Next.js 开发服务，端口
3000）在 19:18～19:44 的提交量由 14.93 GiB 增至 19.85 GiB；最后系统提交量
44.90 / 45.12 GiB。进程于 17:19:10 创建，19:47 重启时结束。

本次短时实验没有复现这个持续增长过程，不能声称已找到或修复了 20 GiB 的
精确泄漏根因。已证实并处理的是开发缓存的大块缓冲分配、默认重复启动以及
缺少持续内存记录的问题。根目录警告也已修正，但没有证据证明它导致泄漏。

## 历史证据

- 17:18:55 的会话命令在仓库执行 `pnpm dev`，启动 `apps/site` 的 `next dev`。
- 后续会话明确记录 `Port 3000 is in use by process 34920`，另开 3001。
  两个服务的输出目录都是 `apps/site/.next`，直到重启仍未退出。
- 原服务日志有一次文章请求、14 条完成编译记录。日志不足以重建浏览器全部活动。
- 当天 16:27 和 17:06 的耗尽事件还记录了 Clash Verge 的 13.56 / 13.76 GiB
  提交量；它是独立的异常，不能因修复网站配置而视为已解决。

## 本次实验

所有请求使用本机 HTTP；只启动本次实验的服务，结束时仅停止这些服务。
临时探针记录 RSS、JS 堆、external/ArrayBuffer，并捕获超过 16 MiB 的 Buffer
分配调用栈。探针有退出阈值，没有尝试把机器再次推至内存耗尽。

1. 单实例首次访问文章约 15～20 秒；连续 6 次重复访问均为 200，约 0.1 秒。
   请求后的内存能回落，未复现逐请求泄漏。
2. 启动第二个实例共享 `.next` 后，第一个实例的文章短暂返回 404，随后恢复。
   证实构建目录干扰；两个实例并未在短时实验中持续涨到数 GiB。
3. 在原配置、Next 默认堆设置下访问文章，并间隔 4 秒触碰 CSS 文件时间戳
   6 次（之后恢复时间戳），触发重新编译。调用栈确认 Webpack 的 gzip/gunzip
   缓存流每次申请 100 MiB Buffer。
4. 修改根目录与开发缓存压缩配置后，在相同默认堆设置下重复请求和触碰操作。

| 指标 | 原配置 PID 25744 | 修改后 PID 34836 |
| --- | ---: | ---: |
| 采样窗口 | 约 207 秒 | 约 98 秒 |
| 100 MiB Buffer 累计分配次数 | 67 | 0 |
| external 采样峰值 | 1261 MiB | 212 MiB |
| RSS 采样峰值 | 1020 MiB | 1141 MiB |
| 末次 RSS | 600 MiB | 574 MiB |

峰值是 5 秒间隔的采样值，可能漏掉瞬时峰值；窗口不同，也不是严格的长期
基准测试。67 次是累计分配次数，不是同时保留 6.7 GiB。结果支持“减少缓存
Buffer 分配”，不支持“整体 RSS 峰值下降”或“原泄漏已根治”。

原始实验数据在仓库忽略目录 `tmp/memory-diagnosis/`，不会随代码提交。

## 已落实的防护

- 将 Next 的 `outputFileTracingRoot` 固定为仓库，消除误选用户目录的警告。
- 仅开发阶段关闭 Webpack 磁盘缓存的 gzip 压缩；保留磁盘缓存。
  生产阶段不安装自定义 webpack 回调，避免影响默认构建 worker 行为。
- `pnpm dev` 经 `scripts/dev.mjs` 启动，默认绑定 `127.0.0.1:3000`。
  默认重复启动报端口占用，不再自动另开 3001。直接执行 `next dev` 或显式
  换端口仍可绕过这一防护，不应同时运行多个实例共享 `.next`。
- 默认 `NODE_OPTIONS` 添加 1536 MiB 老生代堆限制；保留用户显式设置的堆额度。
  Next 15 原本默认使用物理内存的一半作为老生代额度。
- 每 10 秒记录一次进程内存到 `apps/site/tmp/dev-memory/<PID>.jsonl`，单文件
  超过 1 MiB 后轮换保留一份 previous。只记数字，不记录环境变量和页面内容。
- RSS 或 `heapTotal + external` 连续三次超过 3 GiB 时，记录后退出该进程。
  这不是 Windows 提交量的硬限制；采样可能遗漏快速暴涨，原生分配也不一定
  完整包含在 JS/external 指标中。不能保证阻止所有内存耗尽情况。

- 内存保护、Markdown、文章加载：3 个测试文件，12 个测试通过。
- 默认重复启动报告 `EADDRINUSE`，没有留下第二个监听服务。
- 原文章页面返回 HTTP 200，工作区根目录警告消失。
- `git diff --check` 通过。
- 全量 `tsc --noEmit` 被原有测试夹具缺少 `hidden` 字段的 6 处错误阻塞，涉及
  `post-card.test.ts`、`agent-tools.test.ts`、`blog-pet.test.ts`，本次未修改这些文件。

后续若再次增长，应先读取对应 PID 的采样，判断 JS 堆、Buffer 或其余原生
内存哪一类增长，再针对那一类采集堆/分配证据。当前没有足够证据归因到某个
具体文章、高亮规则或依赖版本漏洞。
